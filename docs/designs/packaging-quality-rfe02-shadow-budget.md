## 根因与复现

使用 investigate 的复现→单变量→回归顺序。目录 `/tmp/beian-f-shadow-njKNKl`，包含 `probe.py`、`run.py`、`verify.py`、完整进程日志、每轮 JSON 回执与差异统计。源为上一轮已绑定身份的 F blend，不重新生成几何，不调灯，不覆盖旧图。

在 `render_still` 前后增加阶段标记，并刷新 Python/C 标准流，重新用 512 MB 阴影池跑文字盒六个 pass：退出码 0，但稳定出现 76 条溢出，正反 `*_set.png` 各 38 条。需求约 2346–2348 页，池容量 2048 页。产品/ground 阶段未记录该警告。之前尾部输出不能定位阶段的问题已消除。

只将 `scene.eevee.shadow_pool_size` 从 `512` 调到 `1024`；没有改变 F、分辨率、阴影分辨率下限、材质或相机。相同文字盒六个 pass 警告降到 0，退出码 0。原池约 43.9 秒、新池约 44.8 秒，不作为性能基准。

## 回归结果

- 新池再跑白盒、宽盒、深色盒，加上文字盒共 24 张 3000×3600，所有进程 exit 0，所有完整日志中阴影溢出为 0。
- `verify.py` 验证原池必须复现失败信号、新池四盒必须零警告；新输出/源 blend/脚本哈希匹配，F 灯光与上一轮参数逐项相同，所有对应图片 Alpha 字节相同。
- 本轮 512/1024 成对文字盒：产品和 ground 像素完全相同；两张 set 约 214/217 万像素发生变化，最大通道差 4，平均通道差约 0.186/0.188（8-bit），不是“没有任何变化”。
- 与用户上一轮看过的整批 F full 对照：8 张产品静帧全部像素相同；部分其他 pass 有最大 1 的微小差异。文字盒正面 set 最大通道差 16、平均约 0.219，反面最大差 4。不能把本轮成对最大差 4 推广为与任意历史运行都相同；差异完整记录在 `verification.json`。
- 复用与上轮哈希相同的 `mockupStudio.ts` 合成器，重新导出四盒/双视角/三背景 24 张成片；报告 `compositor-report.json`。没有重写合成公式。预览/下载同像素合同已在前轮对该源码验证，本轮不将其冒称另一次独立对照。
