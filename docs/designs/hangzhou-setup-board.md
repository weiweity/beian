## Problem Statement

所有打开网址的伸美同事，上传文件后运算都发生在杭州那台台式（Hono `:8787` + Python worker + 本机软件）。设置页已经能填飞书 / 百度 / MiniMax / Blender，开工板也能点「检测连通」。魏炜仍觉得这是复杂配置：不知道哪些绿、哪些红；希望飞书、百度、MiniMax「一键授权」；看不懂「本机依赖」；希望推代码到杭州后能扫到 Illustrator 等软件，最好 AI 辅助匹配。

籽烨不进设置。她的痛是左右分屏对字，不是 API Key。

## Demand Evidence

- 刘籽烨：展示后催上线，原话「没有的话，一眼望不到的头的加班。」尚未验证她在现网页上独立签完真稿。
- 魏炜（本轮）：密钥是他填；MiniMax 点检测显示通了，仍不信任；本机依赖四个字看不懂；要傻瓜开工和扫 Adobe。
- 行为：设置页、探测、密钥分组已在 v0.10。一键拿百度 OCR 权限、Illustrator COM 出图尚未发生。

## Status Quo

- 计算：产品入口应是杭州 `:8787`。当前 `www.jianghua.site` 经常是 Mac 隧道，合 GitHub 不会升杭州。
- 配置：魏炜在设置里粘贴 App ID / Secret / OCR Key / MiniMax Key / Blender 路径。籽烨飞书登录后传 Excel/PDF。
- 打样：平面稿 PDF/AI 进 `workers/packaging`；缺 Blender 会 412。平面 PDF 出图已用 pymupdf，杭州不靠 qlmanage。Illustrator COM 仍写在章程 8/31 不做。
- 探测：开工板对 feishu / baidu / python / blender / lark / minimax 调 probe。「通了」没有说通的是哪一种接口。

## Target User & Narrowest Wedge

- **审稿验收人：** 刘籽烨。8/31 = 她自己完成一单 Excel↔PDF 终审。
- **开工板用户：** 魏炜。把杭州机箱点绿，少喊自己填错 Key。
- **楔子（实现仍按所选 Approach C 铺开）：** 先让开工板用绿/红 + 人话说明「通了什么」；飞书登录保持现有 OAuth；推送尽量跟已登录 `open_id`；百度/MiniMax 做控制台逐步指引（不是假装零 Key）；本机扫 Blender 与 Illustrator 路径；打样收到 `.ai` 时再用 COM 转图。
- 没有「这周把所有厂商变成一个按钮」。那是愿望，不是厂商协议。

- 不重写对照引擎和 3D 流水线。

## Recommended Approach

**Approach C**（用户 D10 选择）。在现有「外观 / 开工板 / 费用 / 密钥」上加深开工板和本机依赖，不新开第三个 HTTP，不把籽烨验收改成设置页。

### 1. 杭州是唯一算力

- 隧道最终必须指杭州 `127.0.0.1:8787`，不是开发 Mac。
- 访客只上传；OCR / 对照 / 打样 / 本机软件都在这台 Windows。
- 「租户」本轮 = 伸美飞书企业白名单里的同事。不是计费隔离、不是每客一台机。

### 2. 开工板（傻瓜层）

已有虚拟分组「开工板」和 probe 列表。改成：

| 行 | 绿的意思 | 红时下一步 |
|---|---|---|
| 飞书登录 | 网页应用能走完 OAuth | 开放平台创建网页应用；回调 = 对外网址 + `/api/auth/feishu/callback` |
| 飞书推送 | 能发给当前登录（魏炜） | 行右测试发给 `wb_session`。籽烨接收人在飞书推送页单独测（D11） |
| 百度 OCR | 用**对照会调用的那个** OCR 接口探测成功 | 控制台建应用，复制 API Key / Secret；向导逐步截图指引，不是静默 OAuth |
| MiniMax | 写明探测的是对话/余额/哪一个模型 | Key 仍要粘贴。模型列表只留国内可用、包装理解需要的，不铺全球模型（学 cc-switch 的「短列表」不是抄它的产品） |
| Python | worker 解释器在 | 指向 `apps/web/backend/.venv` |
| Blender | `findBlender()` 或设置路径存在 | 安装或扫盘填入 |
| Illustrator | 扫到安装路径 | 仅路径绿。转图见 §4 |

进度条 = 上表已绿条数 / 总条数。不要环形仪表。失败文案禁止只写 `ok: true`。

### 3. 「一键」边界

- **飞书登录：** 已是 OAuth。开工板不要再要第二套登录。
- **飞书推送：** 与登录不同 scope。尽量「用我现在的身份接收」；机器人推送走一次授权。
- **百度 OCR：** 本仓库是 `BAIDU_OCR_API_KEY` + `SECRET`。向导 = 打开控制台该点哪 + 粘贴 + 用真 OCR 接口复测。做不到零 Key 就写「做不到」，不要假按钮。
- **MiniMax：** 同上。探测「通了」必须带：测了哪个 URL、哪个模型、是余额还是对话。模型选择器只列国产/国内可用项。

### 4. 本机依赖与扫描

「本机依赖」= 杭州 Windows 上的可执行文件，不是云权限。

- 按钮「扫描这台电脑」。Windows：常见安装目录 + `where`。
- 必扫：Blender（已有 `findBlender()`）、Python venv。
- 必扫并显示：Illustrator（路径、版本若能读到）。
- 可显示、不阻塞开工：其他 Adobe。AI 辅助 = 对扫描结果做名称匹配和「缺了打样会怎样」的人话，不在磁盘上乱执行未知 exe。
- 扫到的路径写入设置，需魏炜确认后保存。

### 5. `.ai` → 栅格（COM）

- 触发：打样台上传 `.ai`，且已确认 Illustrator 路径。
- 行为：本机 COM 打开、导出 PNG/PDF 到该打样作业目录，再交给现有 packaging worker。失败写短中文（没装、COM 被拒绝、文件打不开），412/对照中断同类，不装可用。
- 不是 8/31 籽烨验收。不是 GLB 页内旋转。不是 qlmanage。
- 没有 Illustrator 时：`.ai` 拒绝并指引扫盘，不要静默当 PDF。

### 6. 明确不做（本设计）

- 外卖多租户、每客隔离算力、计费 SaaS。
- 把 8/31 验收改成「设置全绿」。
- 用 COM 替代她打印手折拍照交差。
- 新云、映射端口、Redis/SQLite 通用队列。
- 把 FastAPI 38 条路由复活成产品。

### Pass 1 — Information Architecture  6/10 → 10/10

用户打开开工板，60 秒扫描顺序：

```
设置
└ 开工板
   1. 直线进度「N / 7 可用」+ 右侧「下一步：<第一条红>」
   2. 清单里第一条「还缺」行 + 行右主操作（打开向导 / 扫描这台电脑）
   3. 其余行（可用的只留「再测一次」）
```

约束：一屏只留一个实心紫按钮「全部检测」。扫描是描边/白底次按钮，也出现在 Blender、Illustrator 行右。

**D5 = A：** 所有设置分组（含外观、费用、密钥）去掉页头 6 枚 Tag。状态只出现在开工板。禁止 `通` / `不通`。短结果用「可用 / 还缺 / 未测 / 超时」。

**D6 = A：** 行右「打开向导」切到现有内页分组，不新做弹窗、不在开工板里塞密钥框。

| 行 | 绿 | 红时行右按钮去哪 |
|---|---|---|
| 飞书登录 | 网页 OAuth 能走完 | 飞书登录页 + 回调说明；点了就去现有飞书授权 |
| 飞书推送 | 能发给当前登录（魏炜） | 行右「发一条测试」发给 `wb_session` 的 open_id。籽烨作为审稿接收人在飞书推送页单独测 |
| 百度 OCR | 对照会调用的 OCR 接口通 | 百度 OCR 页：逐步说明 + 原 Key 框 + 真 OCR 复测 |
| MiniMax | 写明 GET `/v1/models` 模型列表 | MiniMax 页填 Key；国产短列表 |
| Python | `.venv` 在 | 本机依赖页 |
| Blender | `findBlender()` 或已存路径 | 行右「扫描这台电脑」；结果在本机依赖确认后保存 |
