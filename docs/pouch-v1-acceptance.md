# 膜袋打样 v1 判定标准

状态：`0.21.25.0` 已完成代码与 L0 接线。词表只认「膜袋」；花盒 `box_net` 失败且恰好两块相近闭合刀线才兜底成 3 mm 薄盒。杭州金标未跑；没有金标不得宣称真实膜袋产品能力。

## 现网（已分流，但不是写实袋体）

`factory_input_hold` 的标记只剩 **内包、标贴**。膜袋不再 hold，改成分流。扫文件名、上传标题、图层名。**没有「袋装」。**

- `26G30A-膜袋.ai` 或标题/层名含「膜袋」→ 先按花盒折；折不通且两块相近刀线 → 待选品名面的袋片；否则 `structure_category_unsupported`（膜袋），不要写成「组不成花盒」
- `26H24A-7袋装花盒.ai` → **不当膜袋**，继续走花盒成盒证明（测试已锁）
- 纯 `26G30A.ai`、标题也不写膜袋 → 不会 hold，会进 V2 四面盒身闸，多半「组不成花盒」
- 命中后仍会先跑一轮 Illustrator，在拓扑前拦住

审稿台的「膜袋」按钮走 `pack_profile`（`膜袋|袋装` → 单片条码）。**打样不读 `pack_surface`。** 两套词表不要混：审稿把「袋装」当袋，打样故意不把「袋装」当袋。

V2 在花盒 `box_net` 不能成立后才尝试 `pouch-net-proposal/1`；确认品名面后生成 `resolved-packaging-job/3`，正反面使用真实 artwork，其余四面是纸面，占位深度固定 3 mm。`pipeline.py` 已把 `packaging_family=pouch` 传入 `resolved_job.json`，但当前 Blender `render_job.py` 尚未按 family 分派几何，仍统一调用 `add_box`。因此它是诚实的“薄卡/薄盒预览”，不是有封边、热封口、插底、侧褶或充气体积的袋体。

## 分流闸门

只认文件名 / 标题 / 层名含 **「膜袋」**。不要用货号。不要加「袋装」，否则 7 袋装花盒会被误杀。

一页多袋、内包、标贴、插底自立袋另开产品。

## v1 几何合同

从刀层取闭合外轮廓（填色刀也算 cut）：

1. 恰好两块足够大的闭合外轮廓。
2. 两块形状接近。先按花盒折，折得通仍是花盒。不要把 `dieline.py` 栅格猜测接回 V2。
3. 第三块大轮廓、插底、侧 gusset → 不支持。
4. 绕开 V2 `box_net` 的四+二。最后仍吐六张 `panel_*.png`（正反印刷，侧面纸面），喂现有 `add_box`。
5. 3D 是薄直方体（旧代码 depth 3mm），不是新网格。不要改 `SEMANTIC_FACES`、不要挖袋形、不要只有两张膜。看起来会像卡片，不是充气袋；v1 若接受这个预览，写清楚。

## 杭州金标（产品宣称前）

杭州真稿、不进 git：

- 正：文件名或标题带「膜袋」，两块相近闭合刀线。
- 负：`26H24A-7袋装花盒` 不得出袋子。
- 负：一页多袋 → 不支持。
- 负：一页两套花盒不得当成 3mm 袋。

## 已交代码与剩余边界

- 已交：膜袋从 hold 改成 V2 分流；两块相近闭合刀线走现有「点品名面」；六面仍进 `add_box`（深 3 mm，侧面纸面）；失败文案明确是当前不支持的膜袋类型；负样本「袋装花盒」由 L0 锁定。
- 未交：真实袋体网格、封边/插底/侧褶、软包装形变、透明或金属复合膜材质、杭州真稿 L2、籽烨 UAT。
- 渲染内核怎样显式消费 `packaging_family`、怎样声明能力矩阵，统一见 `docs/adr-007-packaging-render-fidelity.md`。在该 ADR 和杭州金标完成前，不要把薄盒预览改名成“真实膜袋 3D”。
